# spectreasy #63

## DESCRIPTION

* Consider adding an ORCID to the `Authors@R` field.
* The `nnls` package is listed in `Imports`, meaning it is strictly required and
  automatically installed. However, in `calc_residuals.R` and
  `unmixing_matrix.R`, you check for it using `requireNamespace("nnls")`.  If
  it is required, the check is redundant and should be removed. If it is meant
  to be optional, move `nnls` to `Suggests`. Additionally, do not instruct
  users to use `install.packages()` (over `BiocManager::install()`) in
  Bioconductor packages; simply state that the package is required.
* The `plumber` package is listed in `Suggests`, but `launch_gui.R` calls
  `plumber::plumb()` without checking if it is installed. You must add
  `if (!requireNamespace("plumber", quietly = TRUE)) ...` before calling its
  functions.
* Consider adding the fnd (funder) role in Authors@R if this work was
  supported by a grant.

## R

* Several functions are very long (e.g., `build_reference_matrix` is reported
  to be ~700 lines). Consider breaking these down into smaller, focused helper
  functions to improve readability and maintainability.

* Note that there are quite a few functions that are over 10 in cyclomatic
  complexity (as reported by `cyclocomp`). Consider refactoring these
  functions to reduce complexity, which can improve readability and
  maintainability.

* Reconsider the use of `<<-` in `matrix_utils.R` (line 92) and
  `control_interface.R` (line 495). Global or parent-environment assignment
  makes state changes difficult to track.
* Make sure that `launch_gui` uses files only from the installed package and
  not from the current directory by using `system.file()`
* Check that the user has `npm` installed before trying to launch the GUI, and
  provide a helpful error message if it is not found.
* Avoid saving files for the user without their consent. Either prompt the
  user or simply display the plot and let users save it themselves (in
  `plot_functions.R`, `report_generator.R`, etc.).

* AI Suggestions: In `calc_residuals.R`, the NNLS and WLS methods iterate over
  every cell using a `for` loop (`for (i in seq_len(n_cells))`). For flow
  cytometry data, `n_cells` can easily exceed 100,000. Running `nnls::nnls()` or
  matrix inversion (`solve()`) inside an R for loop for 100,000+ iterations will
  be slow and can create a performance bottleneck. For WLS, consider
  vectorizing the operation if possible, or implementing the per-cell loop in
  C++ using Rcpp and RcppArmadillo for fast matrix operations. For NNLS,
  consider if a block-wise or vectorized NNLS solver can be used, or similarly
  move the loop to C++
* For security reasons, use `host = "127.0.0.1"` instead of `"0.0.0.0"` when
  launching the GUI with `plumber` to restrict access to the local machine
  only.
* `unmix_samples()` writes FCS files to disk by default (`write_fcs = TRUE`).
  If `output_dir` is not carefully specified, it might silently overwrite
  existing files. Warn the user or use a safe naming convention to avoid
  accidental data loss.
*  The package relies heavily on base R matrices and data frames for
   intermediate data representation rather than native Bioconductor classes.
   While `flowFrame` is used for I/O, consider using `flowSet` or
   `SingleCellExperiment` for managing multiple samples and their metadata in
   memory. This would integrate better with the broader Bioconductor
   single-cell ecosystem.
